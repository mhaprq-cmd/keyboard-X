Keyboard X

لوحة مفاتيح Android أصلية مبنية باستخدام Kotlin، مع تطبيق لإدارة اللغات والمظهر والإعدادات والدعم.

حالة المشروع

- الإصدار: "0.1.0"
- المرحلة الحالية: "7.3" — مطابقة واجهة التطبيق مع المرجع البصري الرسمي.
- منصة التطوير والبناء: GitHub Actions.
- اختبار التطبيق على جهاز Android فعلي: تم.
- حالة مطابقة التصميم المرجعي: قيد التنفيذ.
- الحالة النهائية للمرحلة: لا تُعد المرحلة مكتملة حتى تنفيذ التعديلات البصرية، واجتياز إجراءات GitHub Actions، والتحقق من النتيجة على الجهاز الفعلي.

«نجاح البناء لا يثبت وحده التطابق البصري أو سلامة جميع وظائف لوحة المفاتيح.»

نبذة عن المشروع

Keyboard X تطبيق Android Native، وليس تطبيق ويب أو PWA مغلفًا داخل تطبيق Android.

يعتمد المشروع على Kotlin وخدمة إدخال Android الأصلية (Input Method Editor — IME)، ويهدف إلى توفير تجربة كتابة بالعربية والإنجليزية مع واجهة قابلة للتطوير.

قواعد إلزامية لتطبيق المرجع

قبل إجراء أي تعديل على واجهة التطبيق، يجب فتح الصورة المرجعية ومراجعتها بصريًا، ثم فحص ملفات التنفيذ الحالية والموارد المرتبطة بها.

المطلوب هو تنفيذ التصميم الظاهر في المرجع على التطبيق الفعلي، وليس إنشاء تصميم مشابه أو تقريبي.

يجب الالتزام بالعناصر التالية بحسب ما يظهر في الصورة:

- ترتيب العناصر والبطاقات.
- أبعاد البطاقات وارتفاعاتها وعروضها.
- المسافات الأفقية والرأسية بين العناصر والبطاقات.
- ألوان الخلفيات والبطاقات والحدود والنصوص والعناصر التفاعلية.
- استدارة الزوايا وسماكة الحدود.
- الأيقونات وأحجامها ومحاذاتها.
- أحجام النصوص وأوزان الخطوط ومحاذاتها.
- المسافات الداخلية للبطاقات والهوامش الخارجية.
- شريط التنقل السفلي وعناصره وحالات التحديد.
- التناسق البصري بين الصفحات وعناصر الواجهة المشتركة.

لا يجوز تغيير تفاصيل التصميم المرجعي بناءً على تفضيل شخصي أو تخمين، ولا يجوز وصف التصميم بأنه مطابق قبل فحص النتيجة الفعلية ومقارنتها بالصورة.

إذا تعذر تحديد قيمة دقيقة من الصورة وحدها، فيجب توضيح ذلك والتحقق من القياسات المتاحة بدل اختراع قيمة والادعاء بأنها مطابقة.

تطبيق المرجع على اللغتين

يجب أن تحافظ الواجهة العربية والواجهة الإنجليزية على التصميم نفسه، مع مراعاة اتجاه النص الصحيح لكل لغة، وعدم السماح لتغيير اللغة بتغيير ترتيب التصميم أو المسافات دون مبرر.

يجب فحص البطاقات والنصوص والمحاذاة في اللغتين، والتأكد من عدم تلاصق البطاقات التي ينبغي فصلها بمسافات واضحة.

نطاق المرجع

الصورة الحالية مرجع لصفحة الإعدادات والعناصر الظاهرة فيها. ولا تُعد الصورة وحدها دليلًا على تفاصيل الصفحات التي لا تعرضها.

تُطبّق قواعد التصميم المشتركة على بقية الصفحات، أما التفاصيل الخاصة بكل صفحة فتُراجع وفق مرجعها البصري عندما تتوفر صور مرجعية إضافية.

آلية التحقق من التطابق

1. مراجعة الصورة المرجعية قبل التعديل.
2. فحص ملفات XML وKotlin وموارد الألوان والخلفيات ذات الصلة.
3. تنفيذ التغييرات على الملفات الحالية دون إنشاء بدائل مكررة بلا ضرورة.
4. تشغيل إجراءات GitHub Actions وانتظار نتيجتها.
5. تثبيت النسخة الناتجة على جهاز Android فعلي.
6. مقارنة الشاشة الفعلية بالصورة المرجعية ومراجعة الفروق المرئية.
7. إصلاح الفروق المتبقية قبل إعلان اكتمال المطابقة.

نجاح اختبارات البناء وحده لا يعني أن التصميم أصبح مطابقًا.

الواجهات والوظائف

يتضمن المشروع بنية واجهة تشمل:

- الصفحة الرئيسية.
- قسم اللغات.
- قسم المظهر.
- قسم الإعدادات.
- تفضيلات التطبيق ولغة الواجهة.
- صفحات حول التطبيق والدعم والخصوصية وشروط الاستخدام.
- وظائف تفعيل لوحة المفاتيح واختيارها.
- صفحة الإبلاغ عن مشكلة.

وجود واجهة أو عنصر في التطبيق لا يعني بالضرورة أن جميع وظائفه قد خضعت لاختبار عملي.

تعديل خيار الملكية الفكرية

من متطلبات إعادة تصميم الواجهة إزالة خيار «الملكية الفكرية» من واجهة التطبيق في اللغتين العربية والإنجليزية.

يجب التحقق من مصدر إضافة هذا الخيار في Kotlin ومن الموارد المرتبطة به، وإزالة ظهوره من واجهة المستخدم بصورة صحيحة، دون حذف ملفات أو نصوص أخرى غير مرتبطة بالمطلوب دون مراجعة.

متطلبات الحفاظ على الوظائف

يجب أن تحافظ تعديلات التصميم على وظائف لوحة المفاتيح الأصلية، بما في ذلك:

- تفعيل Keyboard X من إعدادات Android.
- اختيار Keyboard X باعتبارها لوحة المفاتيح المستخدمة.
- الكتابة بالعربية والإنجليزية داخل التطبيقات الأخرى.
- عمل التنقل بين صفحات التطبيق والعودة منها.
- استمرار عمل إعدادات اللغة والمظهر المتاحة.

تُراجع الوظائف عمليًا على الجهاز، ولا يُفترض اكتمالها لمجرد نجاح البناء.

البناء والاختبارات باستخدام GitHub Actions

يُستخدم GitHub Actions لبناء المشروع وتشغيل الاختبارات المحددة في ملفات سير العمل.

لمراجعة النتيجة:

1. افتح تبويب Actions في المستودع.
2. افتح أحدث تشغيل مرتبط بالتعديل.
3. تحقق من نتيجة خطوات البناء والاختبارات.
4. إذا أنتج الإجراء ملف APK ضمن Artifacts، نزّله وثبّته على جهاز Android.
5. اختبر الواجهة والوظائف الفعلية قبل اعتماد التعديل.

رابط الإجراءات:

https://github.com/mhaprq-cmd/keyboard-X/actions

لا يُعد نجاح إجراء إصلاح المسارات أو نجاح بناء APK وحده إثباتًا على مطابقة الواجهة للمرجع.

إرشادات التطوير

- الحفاظ على طبيعة المشروع كتطبيق Android Native.
- استخدام Kotlin وبنية Android الحالية.
- تجنب الاعتماديات غير الضرورية.
- فحص الملفات الحالية والملفات المرتبطة قبل إجراء أي تعديل.
- عدم إنشاء ملفات أو موارد مكررة دون ضرورة موثقة.
- الالتزام بالمرجع البصري الرسمي قبل كل تعديل بصري.
- عدم إجراء تغييرات وظيفية غير مطلوبة ضمن إصلاحات التصميم.
- انتظار نتيجة GitHub Actions بعد كل تحديث.
- اختبار التطبيق الفعلي عندما يكون التغيير متعلقًا بالواجهة أو الوظائف.
- تحديث هذا الملف عند حدوث تقدم فعلي، مع الحفاظ على المعلومات السابقة التي لا تزال صحيحة.

خطة العمل الحالية

1. تثبيت الصورة المرجعية في المستودع وتوثيقها — تم.
2. اعتماد الصورة مرجعًا بصريًا رسميًا — تم.
3. مراجعة واجهة التطبيق الحالية ومقارنتها بالمرجع.
4. تنفيذ تعديلات الواجهة اللازمة لتحقيق المطابقة.
5. إزالة خيار الملكية الفكرية من الواجهة العربية والإنجليزية.
6. تشغيل GitHub Actions بعد التعديلات.
7. تثبيت النسخة الجديدة واختبارها على جهاز Android فعلي.
8. مراجعة الفروق المتبقية وإصلاحها.
9. اعتماد المرحلة بعد استيفاء معايير القبول، وتحديث حالة المشروع في هذا الملف.

الترخيص

يُرجى الرجوع إلى ملف الترخيص الفعلي الموجود في المستودع لتحديد شروط الاستخدام وإعادة التوزيع والتعديل. لا يُفترض وجود ترخيص مفتوح المصدر أو منح أذونات غير منصوص عليها في الترخيص المعتمد.
